# `zsfinal` — final zero-shot shadow ablation (self-contained)

The clean, apples-to-apples zero-shot shadow-loss-reweight ablation for the paper.
Everything for the comparison lives here (data manifests + driver) or is derived from
it deterministically. Full rationale: `paper/zeroshot_training_provenance.md`.

## What makes this "clean" (vs the older mixed checkpoints)
Every cell is trained by **one** trainer (`deepforest_custom/train_deepforest.py`) on
**one** data manifest, with an identical recipe. The only thing that varies across cells
is the shadow loss weight and the blind toggle — a true single-variable ablation. This
removes the three confounds in the historical zero-shot set (trainer fork
`deepforest_custom` vs `phase30/lib`, photometric vs crop-only augmentation, WON-shrink
on vs off) documented in the provenance report.

## The five cells
| run_name | weight | blind | role |
|---|---|---|---|
| `zsfinal_s1` | 1 | no | no-shadow baseline (×1 = no reweighting) |
| `zsfinal_s2` | 2 | no | shadow |
| `zsfinal_s4` | 4 | no | shadow (same weight as the old phase22_B_L4) |
| `zsfinal_blind_s2` | 2 | yes | specificity control @ weight 2 |
| `zsfinal_blind_s4` | 4 | yes | specificity control @ weight 4 |

(`sN` = shadow loss weight N, matching the `ablation_tcd_s0/s2/s4` convention.
`s1` is the neutral no-shadow baseline — weight 1, not the old weight-0 "s0".)

`blind` = `SHADOW_BLIND_CONTROL=1`: upweight the same NUMBER of GT boxes per image as the
shadow logic would, but chosen at random (re-drawn every step). If blind ≈ shadow, the
gain is generic hard-example mining; if shadow > blind, the shadow prior is doing the work.

## Pinned recipe (identical for all five — the canonical family-A recipe)
- base: weecology/deepforest-tree (HF pretrained), no `--checkpoint`
- 50 epochs · **EarlyStopping(monitor=val `map`, patience 10)** · `save_top_k=1` (best epoch)
- lr 1e-3 · batch 16 · RandomCrop 400 only (no flip, no photometric) · ToTensorV2
- **WON bbox-shrink ON** (deepforest_custom default; WON GT boxes → 50 % area)
- shadow angle auto-derived from the CSV `shadow_angle` column
- accelerator MPS · `DF_NUM_WORKERS=0` (macOS DataLoader fix)

## Data
`train.csv` / `val.csv` here are generated by `build_csvs.py` from
`phase22/phase22_{train,val}.csv` (the original BRU/WON/NEON manifest), with paths
remapped to the current repo root and sub-400 px tiles dropped. They are **gitignored**
(machine-specific absolute paths); `build_csvs.py` is the tracked, reproducible source.

- train: **128 images** (BRU 41 / NEON 55 / WON 32), 1402 boxes
- val: **36 images** (BRU 10 / WON 9... NEON absent from val), 443 boxes
- **Dropped tiles** (one per split): `bru_tile_856_4400_rot285.tif` (train) and
  `bru_tile_456_4400_rot183.tif` (val), both **400×200 px** rotation-crop strips. The
  400×400 `RandomCrop` in deepforest_custom has **no padding** → albumentations raises
  `CropSizeError` on any tile whose shorter side < 400, so these strips cannot be sampled
  and could not have trained the originals either. Dropping them is forced by the crop
  geometry, not an arbitrary filter.

## Run (training)
```bash
./venv310/bin/python deepforest_custom/zeroshot_final/build_csvs.py   # (re)build manifests
caffeinate -i bash deepforest_custom/zeroshot_final/train_all.sh       # ~30–45 min/cell on MPS
```
Checkpoints → `checkpoints/zsfinal/zsfinal_<cell>/` (best-mAP epoch kept; auto-resumes).

## Eval (after training) — outputs to benchmark_results_holdout/
Re-infer every cell through ONE pinned foxtrot→SAM pipeline, writing geojsons + the automatic
`summary.json` provenance to **`benchmark_results_holdout/zsfinal_<cell>/`**, e.g.:
```bash
caffeinate -i ./venv310/bin/python phase30/benchmark.py \
  --models checkpoints/zsfinal/zsfinal_s4/deepforest_final.pth \
  --names  zsfinal_s4 \
  --holdout-dir data/tcd/images/data/tcd/val \
  --shadow-model solar/shadow_regression/output/shadow_model_combined_best.pth \
  --sam-model vit_l --sam-checkpoint sam_vit_l_0b3195.pth \
  --df-confidence 0.001 --max-dets 512 --pred-score-thresh 0.0 \
  --skip-existing --output-root benchmark_results_holdout
```
- **SAM: pinned `vit_l`** (`sam_vit_l_0b3195.pth`, repo root) — Tom's decision 2026-06-11. All
  cells use the same SAM, so it is a constant across the ablation, not a confound.
- **Score floor (DISTINCT from `--df-confidence`) — must be addressed before eval.** The DeepForest
  RetinaNet has its OWN internal `score_thresh = 0.1`, applied *inside* `df_model.model(...)`
  (`foxtrot.py:854`) and so BEFORE foxtrot's post-filter `score >= confidence_threshold`
  (`foxtrot.py:859`, fed by `--df-confidence`). `--df-confidence` can only remove boxes that already
  cleared 0.1 — it cannot recover the sub-0.1 PR tail that mAP integration needs. Until the model's
  `score_thresh` is lowered (set `df_model.model.score_thresh ≈ 0.001` after build/eval in BOTH
  load branches), every cell is truncated at 0.1. Within zsfinal this is *internally* fair (all five
  cells floored identically), but it understates absolute mAP and is not comparable to the old
  phase22 0.498 (whose geojsons reach ~0.001). Recommendation: apply the patch so the numbers are
  faithful and comparable. See `phase30/zeroshot/REINFER_PLAN_vitl.md` §4.

Then add the rows to `benchmark_results_holdout/ALL_models_holdout_table.md`.
